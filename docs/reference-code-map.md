## Hard-won facts (don't re-learn these at the hackathon)

- Avatar model `gemini-3.8-live` exists **only in us-central1**; text models only in **global**.
- Avatar quota is **3 concurrent sessions per project** with lagged enforcement; 5+ at once locks the project for
  ~10–13 min. Seats are spread over `LIVE_PROJECTS` (2 projects → 2 avatars each) and opened 400 ms apart.
  Always close sockets cleanly (`pagehide` → `controller.dispose()`).
- Avatar video is a **continuous** fMP4 stream (idle blinking between turns). One SourceBuffer per seat, never reset,
  trim every 5 s, chase the live edge. `video_bitrate_bps: 500000` → ~0.76 Mbps per avatar.
- Speaking state comes from `outputTranscription` / `turnComplete`, never from video.
- `turn_complete:false` context never triggers a reply — that's how investors "hear" each other.
- Default VAD cuts the founder off at 0.44 s pauses → `silence_duration_ms: 1200`.
- The scribe is `gemini-3.5-transcribe-live-preview` @ global with VAD off and ONE activity per pitch.
- Report/fact-check latency is spiky (search calls 8–55 s) → analysis runs in `after()` and the report page polls.
- Model-estimated metrics are wrong → compute WPM/fillers/talk-time in code (`lib/server/metrics.ts`).
- `@azure/communication-react` declares React <19 peers: install anyway (`pnpm add` warns, works). Import it only from
  a `next/dynamic(..., { ssr:false })` component and call `registerIcons(DEFAULT_COMPONENT_ICONS)`.
- pnpm 11 exits 1 when dependency build scripts aren't approved: write `allowBuilds` in `pnpm-workspace.yaml` first
  (bootstrap.sh does).
- 3.8 Live has proactive audio permanently on → an investor may stay silent after an answer; the controller nudges it
  after 3.5 s. Investor VAD: `silence_duration_ms 1200` + `END_SENSITIVITY_LOW` (fewer mid-sentence cut-ins).
- There is no "user emotion" API in Live; vocal confidence comes from `/api/delivery` (gemini-3.8-flash listening to
  ~45 s clips). Investors get those notes as silent context, so confidence sways their verdicts.
- Automated Chrome on macOS hangs on getUserMedia (OS permission) even with fake-device flags → e2e injects fake media.
